# Обновление CRM для магазина одежды — 12.11.2026

## Реализовано
- События SSE: изменения сделок, заказов, клиентов и сообщений обновляют открытые экраны. Автопереподключение, резервная синхронизация 30 секунд. Ненавязчивые уведомления об изменениях; уведомления о входящих сообщениях. Закрытый браузер не получает push.
- Inbox: агрегированные запросы вместо запросов для каждой карточки; последние 200 сообщений, загрузка ранней истории по кнопке.
- Непрочитанные: персональный статус менеджера, подсветка, счётчик, ручная отметка. Это статус CRM, не обещание отправки read receipt в Instagram/WhatsApp.
- Фото, видео и аудио в чатах; загрузка/отправка файлов до 16 МБ. PDF — WhatsApp и внутренние документы; Instagram — фото, аудио и видео. Голосовые можно прикрепить файлом; записи с микрофона пока нет. Файл и текст отправляются отдельными сообщениями.
- Файлы сохраняются в PostgreSQL, не на эфемерном диске Railway. Просмотр по подписанным ссылкам на 30 минут; ссылки используются провайдером для загрузки исходящих вложений. Неподдерживаемые/недоступные входящие файлы требуют открытия исходного мессенджера. Старые текстовые заглушки автоматически восстановить невозможно.
- Чеки и фото/видео товара отдельно внутри карточки сделки. Не отправляются клиенту автоматически. Значки наличия документов на канбане.
- Черновики в текущей сессии браузера, быстрые ответы, Ctrl+Enter.
- Фильтры: город, менеджер, канал, непрочитанные, ожидание ответа, дата создания, этап, статус оплаты, диапазон суммы. Сохранённые наборы — в этом браузере для пользователя.
- Аналитика: выручка оплаченных заказов после скидок, средний чек, популярные товары/размеры/цвета, покупатели, повторные покупки в периоде, конверсия источников и среднее время первого ответа. Даты фильтра — даты создания заказа/обращения в UTC, не фактической оплаты. Не учитываются неизвестные продажи вне CRM; нет анализа намерений или ИИ-классификации.
- Instagram: получение @username, кэш на сутки, повтор при отказе через час; вручную введённое имя сохраняется. ID остаётся внутренним ключом. Один подключённый IG аккаунт; остальные два требуют отдельного этапа настройки.

## Эксплуатация
- Текущая конфигурация: один API worker, одна реплика. SSE invalidation хранится в памяти; после переподключения клиент перечитывает состояние БД. Для нескольких реплик нужен общий event bus.
- Медиа увеличивают размер PostgreSQL. При заметном росте объёма перенести бинарные данные в приватное S3-совместимое хранилище; обеспечить резервное копирование и политику хранения. Файлы ещё не проходят антивирусное сканирование.
- Разрешённые типы: JPEG, PNG, WebP, MP4, M4A, MP3, OGG, WAV, PDF. Сервер проверяет заголовок формата и размер. Входящие Instagram CDN-файлы сохраняются в фоне; неудачная загрузка обозначается как недоступная.
- Проверка HMAC Instagram сохранена. Ключи и токены не выводятся в журналы. Добавлены только таблицы media_assets и instagram_profiles; существующие таблицы/данные не удаляются.
- После деплоя обновить страницу. Проверить по одному реальному фото, аудио и видео в обе стороны на тестовых аккаунтах. Автоматические тесты используют mock провайдеров, не доказывают доставку реальному получателю.

## Следующие полезные улучшения
1. Каталог одежды: артикул, размеры/цвета, остатки по городам, резерв товара из диалога, подбор готовых фото.
2. Напоминания и норматив времени ответа: например, выделять необработанные обращения через 5/15 минут, назначать дежурного менеджера.
3. Доставка/самовывоз: адрес, дата, статус, стоимость; возвраты и обмен размеров с корректировкой аналитики.
4. Сверка оплаты: чек — подтверждающий файл, но не автоматическое подтверждение поступления денег. Интеграция банка или ручная проверка ответственным.
5. Три Instagram-аккаунта с привязкой к городам и независимыми токенами. Не объединять покупателей по совпавшему нику.
6. Управляемые шаблоны ответов и папки медиа, запись голосовых, поиск по тексту переписки, назначение диалогов менеджерам.
7. Мониторинг отключений WhatsApp и уведомление администратору; журнал попыток доставки и защита от повторной отправки после сетевого тайм-аута.
8. Фактические даты оплаты, себестоимость, прибыль, возвраты, экспорт отчётов. Не подменять прибыль выручкой.

## Проверка локально
```
python -m unittest discover -s backend -p "test_*.py"
node --test whatsapp/test.mjs
npm --prefix frontend ci
npm --prefix frontend run build
node frontend/tests/inbox.cjs
```
Для последней команды требуется Playwright и установленный Chrome. Backend-тесты используют отдельную SQLite в памяти. Не запускать docker compose down -v.
