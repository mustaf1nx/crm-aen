# WhatsApp: тестовое подключение и новый inbox

В CRM откройте **Сообщения → Подключения → Подключить по QR** под администратором.
В WhatsApp тестового номера: **Связанные устройства → Привязать устройство**.
После привязки отправьте на тестовый номер новое личное текстовое сообщение с другого телефона.
Появятся клиент, сделка и диалог. Ответ можно отправить из карточки сделки или мессенджера.

Это неофициальное подключение Baileys, без использования платного Meta Cloud API.
Возможны блокировка номера, разрывы сессии и изменения протокола. Используйте отдельный тестовый номер.
Сервер и его интернет должны работать постоянно. Расходы Railway остаются.
Отключить связь можно в WhatsApp телефона в разделе связанных устройств.

## Что поддерживается

- Личные новые сообщения; текстовые ответы. История до подключения не импортируется.
- Для медиа отображается подпись или явное уведомление открыть вложение на телефоне. Отправка медиа пока не реализована.
- Группы, статусы, рассылки не импортируются. Автоматических рассылок нет.
- Один номер на экземпляр сервиса. Город задаётся WA_CITY_NAME (по умолчанию Семей).
- Непрочитанные считаются персонально для каждого сотрудника, сохраняются в базе.
- Браузерные уведомления требуют разрешения и открытой вкладки. Закрытый браузер push не получает.
- Карточка сделки: переписка, имя/телефон клиента, ответственный, этап, заметки, заказы, внутренние комментарии и история изменений.

## Развёртывание

Корневой Dockerfile собирает frontend, FastAPI и Node bridge. `python start.py` запускает оба процесса.
Bridge слушает только 127.0.0.1:8090; API обращается к нему с одноразовым ключом процесса.
Используются существующие DATABASE_URL, SECRET_KEY и PORT. Дополнительные токены Meta для WhatsApp не нужны.
На Railway достаточно Git push: сборка и healthcheck выполняются по railway.json.
Запуск этого образа локально требует PostgreSQL; старый backend-only Docker Compose запускает Instagram без WhatsApp bridge.

Сессия хранится в PostgreSQL (wa_auth) с AES-256-GCM, ключ выводится из SECRET_KEY.
Очередь событий wa_event_queue также зашифрована и повторяет доставку после сбоев backend.
Ротация SECRET_KEY требует отдельной миграции зашифрованного состояния либо новой привязки WhatsApp.
Таблица instagram_read_states добавляется автоматически. Существующие таблицы и данные не удаляются.
Общие диалоги используют существующие таблицы с пространством account_id `wa:` для WhatsApp.
Привязка и QR доступны только администратору; менеджеры видят переписки только своего города.
Сессия защищена PostgreSQL advisory lock от двух одновременно работающих копий bridge.

Не запускайте `docker compose down -v`. Не копируйте .env, QR или ключи сессии в Git.

## Проверки

- Backend: `python -m unittest -v test_instagram` из backend (одноразовая SQLite).
- WhatsApp: `npm ci && npm test` из whatsapp.
- Frontend: `npm ci && npm run build` из frontend.
- UI: установите playwright отдельно, затем `node tests/inbox.cjs` из frontend; нужен Chrome.
  Тест работает с подставными API, не отправляет настоящих сообщений. QA_DIR опционально задаёт папку снимков.
